# 发票要素校验

对一批发票做**能确定性判断**的要素校验，输出逐条问题清单。
纯本地运行，不联网、不上传发票数据。

## 何时使用

- 一批发票录入前先过一遍（"帮我看看这些发票有没有问题"）
- 发现金额与税额对不上（"这张票的税额是不是算错了"）
- 检查有没有重复报销的同一张票（"有没有重复发票"）
- 核验购方纳税人识别号填得对不对（"这个税号是不是填错了"）

## 硬性规则

1. **必须执行脚本，不要凭肉眼判断勾稽关系。** 金额 × 税率 的分位舍入很容易看漏。
2. **不要声称能查发票真伪。** 真伪只有税局查验接口能确定，本工具做的是**要素自洽性**校验：
   一张完全伪造但数字自洽的票，本工具查不出来。回答时必须把这条说清楚。
3. **不要声称能算发票号码的校验位。** 中国大陆增值税发票的代码与号码是**流水编号，
   没有公开的校验位算法**。本工具只校验位数（代码 10 或 12 位、号码 8 位）与是否全数字。
   任何"算出校验位"的说法都是编造的。
4. **税号校验位只对 18 位统一社会信用代码做**（GB 32100-2015）。
   15 位老税号没有公开校验位算法，只做"是否 15 位数字"的结构判断。
5. **E 级是错误，W 级是需要人工确认的提醒**，不要把 W301（负数/红字）当成错误直接改数据。
6. 金额容差默认 0.02 元，用于吸收分位舍入；用户要求严格时改成 0.01。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。

```bash
node scripts/invoice.js check <CSV文件> [--delimiter=,] [--tolerate=0.02] [--json]
node scripts/invoice.js one [--code=] [--no=] [--amount=] [--tax=] [--total=]
                            [--rate=0.13] [--date=2026-03-05] [--taxno=] [--json]
node scripts/invoice.js --selftest
```

### 常用示例

```bash
# 校验一批发票
node scripts/invoice.js check ./发票明细.csv

# 严格容差
node scripts/invoice.js check ./发票明细.csv --tolerate=0.01

# 单张快速校验
node scripts/invoice.js one --amount=1000 --tax=130 --total=1130 --rate=0.13

# 只验一个税号
node scripts/invoice.js one --taxno=91330100799655058B
```

## 规则编号

| 编号 | 级别 | 含义 |
|---|---|---|
| E101 | 错误 | 发票代码不是 10 位或 12 位数字 |
| E102 | 错误 | 发票号码不是 8 位数字 |
| E103 | 错误 | 金额 × 税率 ≠ 税额（超出容差） |
| E104 | 错误 | 金额 + 税额 ≠ 价税合计 |
| E105 | 错误 | 税率不在常见税率内（会自动从金额与税额反推） |
| E106 | 错误 | 开票日期无法识别，或在未来 |
| E107 | 错误 | 购方税号校验位错误（GB 32100）或格式不对 |
| E201 | 错误 | 同一代码+号码重复出现 |
| W301 | 提醒 | 金额为负数，确认是否红字发票 |
| W302 | 提醒 | 开票日期距今超过 365 天，确认是否跨期 |
| W303 | 提醒 | 购方税号位数既不是 18 也不是 15 |

常见税率集合：`0% 1% 1.5% 3% 5% 6% 9% 10% 11% 13% 16% 17%`
（含已停用的历史档位，仅供判断合理性，不代表当前政策）。

## 输出解读

```
第 4 行　0330018001/12345678
  金额 2000.00　税额 260.00　价税合计 2265.00
  ✗ E104 价税合计不符：2000.00 + 260.00 = 2260.00，实际 2265.00（差 5.00）
  ✗ E107 购方税号校验位不对：「91330100799655058C」（按 GB 32100 计算）
```

退出码：`0` 无 E 级错误，`1` 存在 E 级错误，可直接用于 CI 或批量卡口。

## 已知取舍

| 情形 | 处理 |
|---|---|
| 发票真伪 | **无法判断**，需税局查验接口 |
| 发票号码校验位 | **不存在公开算法**，只校验位数 |
| 15 位老税号 | 无公开校验位算法，只判断位数与是否全数字 |
| 发票代码中的年份/地区 | 编码规则历经多次调整，**不做提取与比对**，避免误判 |
| 金额为负数 | 判为提醒（红字发票是合法的），不判错误 |
| 一张票多行明细 | 需先按发票号汇总成一行再校验，脚本不做分组合并 |
| 文件编码 | 优先 UTF-8，失败退回 GBK；其它编码（如 UTF-16）不支持 |

## 回答建议

- 先说结论："共 N 张，无误 M 张，问题 K 张（错误 X / 提醒 Y）"，再按规则编号汇总。
- 只报 E 级时不展开逐条；同时有 E 级时，按编号归类说，再给最严重的几条明细。
- 用户问"这张票是真的吗"时，直接说明本工具不查真伪，只能判断要素是否自洽。
- 检出 E201 重复票时，提示按发票代码+号码去重，**不要按金额去重**（不同票可能同额）。
