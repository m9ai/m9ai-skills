# 合同必备条款检查

按法律明文列举的条款清单，检查一份合同文本**有没有提到**这些内容，
并找出未填写的占位符。纯本地运行，不联网、不上传合同内容。

## 何时使用

- 收到一份合同想快速过一遍（"帮我看看这份合同缺什么"）
- 起草完自查（"我这份合同有没有漏条款"）
- 批量检查合同模板是否完备
- 签署前找没填的空（"有没有哪里忘了填"）

## 硬性规则

1. **必须执行脚本，不要凭印象列清单。** 八类条款逐个核对，人眼容易跳。
2. **这是"有没有提到"，不是"是否完备或合法"。**
   条款写了但含糊、前后矛盾、显失公平，脚本一概看不出来。
   所以输出措辞是「未找到相关表述」，**不要说成"缺失""无效""不合规"**。
3. **不要据此下法律结论。** 脚本只能说"文本里没搜到这类关键词"，
   可能是用了别的措辞，也可能写在附件里。最终判断必须由人读原文。
4. **未找到 ≠ 合同有问题。** 例如数量条款写在附件清单里、
   质量要求引用了国家标准，文本正文就不会出现。要先看附件再下结论。
5. 本技能**不做**合同版本比对、金额勾稽、主体资质核验，那是别的工具的事。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。

```bash
node scripts/contract.js check <文本文件> [--type=general|labor|lease] [--json]
node scripts/contract.js --selftest
```

### 合同类型

| `--type=` | 依据 | 检查项 |
|---|---|---|
| `general`（默认） | 民法典第 470 条 | 当事人、标的、数量、质量、价款、履行期限地点方式、违约责任、争议解决、生效终止、签署 |
| `labor` | 劳动合同法第 17 条 | 用人单位信息、劳动者信息、合同期限、工作内容地点、工时休假、劳动报酬、社会保险、劳动保护等 |
| `lease` | 民法典第 704 条 | 租赁物、面积、用途、租赁期限、租金及支付、维修等 |

必备项来自法律明文列举；"生效终止""签署"属实务建议项，缺失只作提示不计入缺失数。

### 常用示例

```bash
# 检查一般合同
node scripts/contract.js check ./合同.txt

# 检查劳动合同
node scripts/contract.js check ./劳动合同.txt --type=labor

# 输出 JSON 便于二次处理
node scripts/contract.js check ./合同.txt --json
```

## 输出解读

```
  ✗ [必备] 数量             未找到相关表述
  ✓ [必备] 争议解决方法         命中 4 处，首次在第 15 行（争议、争议、仲裁）

--- 待填占位符（4 处）---
  第 10 行  …金额 合同总价为人民币 ______ 元,甲方于验收后 30…
```

- `✓` 提到过　`✗` 必备项未找到　`·` 建议项未找到
- 占位符识别 `____`、`（ ）`、`【 】`、`待填`、`TBD` 这类未填内容
- "当事人"一节会检查是否出现了成对的称谓（甲方/乙方 等），只写一方时单独提示

退出码：`0` 必备条款均有提及，`1` 有必备条款未找到，可直接用作批量卡口。

## 已知取舍

| 情形 | 处理 |
|---|---|
| 条款写在附件里 | **看不到**，需人工结合附件判断 |
| 用了别的措辞（如"对价"代替"价款"） | 可能报未找到，属关键词法的固有局限 |
| 条款存在但内容不公平 | **判断不了**，只能由人读 |
| `.docx` / `.pdf` | 不支持，需先转成纯文本再检查 |
| 扫描件 | 不支持，需先做 OCR |
| 中英混排合同 | 只认中文关键词，英文条款会报未找到 |
| 同一条款出现在多份文件 | 一次只检查一个文件 |

## 回答建议

- 先说"依据哪一条、共几项必备条款、未找到几项"，再逐项列出。
- **每次都要补一句**：这只是关键词层的"有没有提到"，不等于条款缺失或不合规，
  可能用了别的措辞或写在附件里。
- 有占位符时优先说——那是签署前必须填的，比条款缺失更紧急。
- 用户问"这合同能不能签"时，明确说明本工具不下法律结论，建议由法务或律师审阅。
- 建议项（生效终止、签署）缺失时语气放轻，不要与必备项混为一谈。
