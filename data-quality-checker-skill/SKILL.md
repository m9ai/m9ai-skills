# 数据质量体检

对一份 CSV 做全面体检，输出每列的分布概览与问题清单。
纯本地运行，不联网、不上传数据。

## 何时使用

- 拿到一份新数据先看一眼（"这份数据质量怎么样"）
- 入库或分析前的检查（"有没有重复行、空值"）
- 排查某列为什么算不对（"金额列怎么有非数字"）
- 校验枚举字段取值是否规范（"状态列有没有乱填的值"）

## 硬性规则

1. **必须执行脚本，不要凭抽样判断。** 空值率与重复行只有全量扫描才知道。
2. **区分 Q 级与 W 级，不要把 W 级说成错误：**
   - `Q0xx` 通常真的是问题（重复行、非法日期、枚举越界、类型混杂）
   - `W1xx` 只是提示，需要结合业务判断（常量列、高基数列、统计异常值）
3. **异常值不等于错误数据。** 一笔真实的大额订单会被 IQR 法则判为异常值，
   那是正常的业务事实。只能说"这个值偏离主体分布，值得看一眼"，不能说"这是错的"。
4. **不修正数据。** 本工具只体检，修改请用 `csv-cleaner`。
5. 空值率阈值默认 30%，不同业务应调整（备注列 75% 为空很正常）。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。

```bash
node scripts/quality.js check <CSV> [--enum=列:值1|值2] [--null-rate=0.3] [--json]
node scripts/quality.js --selftest
```

### 选项

| 选项 | 说明 |
|---|---|
| `--enum=列:值1\|值2` | 枚举列的合法取值，可重复指定多个列 |
| `--null-rate=0.3` | 空值率告警阈值，默认 30% |
| `--delimiter=,` | 强制分隔符 |
| `--json` | 输出 JSON |

### 常用示例

```bash
# 基础体检
node scripts/quality.js check ./订单.csv

# 校验状态列取值
node scripts/quality.js check ./订单.csv --enum='状态:已完成|待付款|已取消'

# 放宽空值率阈值（有些列本来就可以大面积为空）
node scripts/quality.js check ./订单.csv --null-rate=0.8
```

## 规则编号

| 编号 | 级别 | 含义 |
|---|---|---|
| Q001 | Q | 空值率超过阈值 |
| Q002 | Q | 整列为空 |
| Q003 | Q | 存在完全重复的行 |
| Q005 | Q | 枚举取值不在允许集合内 |
| Q006 | Q | 存在首尾空格 |
| Q007 | Q | 形似日期但无法解析（如 2026-02-30） |
| Q008 | Q | 数字与非数字混杂，类型不一致 |
| W101 | W | 常量列：只有一个取值，可能没有信息量 |
| W102 | W | 高基数列：每个值都唯一，疑似主键 |
| W104 | W | 统计异常值（IQR 法则） |

## 输出解读

```
列      类型             非空  空值率  唯一值  最小  最大   均值      示例
金额    mixed               7     13%       6   980  88000  15746.67  1200.00/1500.00
日期    date (1 个非法)     8      0%       7     —      —         —  2026-01-05

--- Q 级（通常真的是问题）---
  ✗ Q005 状态：1 个取值不在允许集合内：已取消

--- W 级（需结合业务判断）---
  ⚠ W104 金额：1 个统计异常值（IQR 法则）：88000
```

类型列的含义：`integer` 整数 / `decimal` 小数 / `date` 日期 / `string` 文本 /
`mixed` 数字与非数字混杂 / `empty` 全空。
日期列里有非法值时会标成 `date (N 个非法)`，而不是笼统降级成 `string`。

退出码：`0` 无 Q 级问题，`1` 存在 Q 级问题，可用作数据入库前的卡口。

## 已知取舍

| 情形 | 处理 |
|---|---|
| 异常值 | 用 IQR 法则（Q1−1.5×IQR、Q3+1.5×IQR），需 ≥4 个数据点 |
| 四分位距为 0 | 不判异常（极度集中的分布） |
| 8 位纯数字日期（20260101） | **不识别**，与订单号无法区分 |
| 枚举集合 | 需用户用 `--enum=` 提供，不内置 |
| 跨列一致性（如 结束日期 ≥ 开始日期） | **不检查**，需人工确认 |
| 编码问题（乱码） | 不检查，请用 `csv-cleaner` 或专门的编码检测工具 |
| 数据量 | 全量扫描，超大文件耗时长 |

## 回答建议

- 先说"几行几列、Q 级几条、W 级几条"，再列重点问题。
- **W 级要用"提示"语气**：异常值、常量列在很多场景下完全合理。
- Q008 类型混杂时，建议用户去看看那列到底混进了什么（示例里会给出值）。
- Q003 重复行要给出具体行号，便于用户直接定位。
- 体检完用户问"怎么修"时，指向 `csv-cleaner`，本工具不做修改。
