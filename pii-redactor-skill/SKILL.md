# 个人信息脱敏

识别文本中的个人信息并替换成掩码，用于对外提供数据、日志脱敏、材料归档前的处理。
纯本地运行，不联网、不上传任何内容。

## 何时使用

- 数据要发给外部前先脱敏（"把这些记录脱敏后再给我"）
- 日志或导出文件里混进了手机号/身份证（"这份导出里有身份证号，处理一下"）
- 归档材料前做隐私处理（"合同扫描件文本要脱敏"）
- 先看看有哪些敏感信息（"这份文件里有敏感信息吗"——用 `scan`）

## 硬性规则

1. **必须执行脚本，不要手工打码。** 手工替换必然漏，且容易漏掉跨行的组合。
2. **不要声称"已完全脱敏"。** 本技能只覆盖下面那几类有确定算法的信息。
   脱敏后仍需人工过一遍——尤其是姓名、住址、单位名这些本技能**不识别**的内容。
3. **不做中文姓名与住址的通用识别。** 中文姓名与地址没有可靠的正则是：
   2–4 字的常见词、带"路/号/区"的普通表述都会大量误报。
   硬做只会让人误以为"已经脱敏干净了"，比不做更危险。这部分由 Agent 阅读理解后处理。
4. **报告默认不回显原始值。** 回显等于把敏感信息再泄露一遍。
   确需原文对照时才加 `--show-original`，并且要提醒用户这份报告本身也是敏感材料。
5. `--out=` 会写文件；不加则输出到 stdout，**不会改动原文件**。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。

```bash
node scripts/pii.js scan   <文件|-> [选项]      # 只报告，不改文本
node scripts/pii.js redact <文件|-> [--out=文件] [选项]
node scripts/pii.js --selftest
```

文件填 `-` 时从 stdin 读取，便于管道使用。

### 选项

| 选项 | 说明 |
|---|---|
| `--types=a,b` | 识别类别，默认 `phone,idcard,bank,email,plate,ipv4` |
| `--id-level=last4` | 身份证掩码：`last4`（默认）或 `keep6` |
| `--out=<文件>` | 写出到文件；不填则输出到 stdout |
| `--show-original` | 报告里回显原始值（默认不回显） |
| `--stats-only` | `scan` 只输出统计，不列明细 |
| `--json` | 输出 JSON |

### 识别类别

| 类别 | 判定方式 | 掩码效果 |
|---|---|---|
| `phone` 手机号 | `1[3-9]` + 9 位数字 | `138****5678` |
| `idcard` 身份证 | 18 位 + GB 11643 校验位 + 出生日期真实存在 | `**************002X` |
| `bank` 银行卡 | 16–19 位 + Luhn 校验 | `************1111` |
| `email` 邮箱 | 标准邮箱格式 | `z***@example.com` |
| `plate` 车牌 | 省份简称 + 字母数字组合 | `京A***23` |
| `ipv4` IP 地址 | 四段且每段 ≤ 255 | `192.168.*.*` |
| `uscc` 统一社会信用代码 | 18 位 + GB 32100 校验位 | `91************058B` |

`uscc` **默认不启用**：18 位纯数字（订单号、流水号）有 1/31 的概率恰好通过校验位，
默认启用会在业务数据里产生难以解释的误报。需要时显式加 `--types=uscc`，或用 `--types=all`。

### 常用示例

```bash
# 先看有什么（推荐先做这步）
node scripts/pii.js scan ./客户名单.csv

# 脱敏后输出到 stdout
node scripts/pii.js redact ./客户名单.csv

# 写到新文件
node scripts/pii.js redact ./客户名单.csv --out=./客户名单_脱敏.csv

# 只处理手机号和身份证
node scripts/pii.js redact ./data.txt --types=phone,idcard

# 管道用法
cat ./log.txt | node scripts/pii.js redact -
```

## 输出解读

```
共发现 5 处
  手机号          1
  身份证号         1
  银行卡号         1
  邮箱           1
  IPv4 地址      1

     1:  9  手机号          138****5678
     1: 25  身份证号         **************002X
```

行号与列号从 1 开始，便于回原文件定位。
`scan` 发现敏感信息时退出码为 `1`，可直接用作 CI 卡口（"提交前不许出现手机号"）。

## 已知取舍

| 情形 | 处理 |
|---|---|
| 中文姓名 | **不识别**，由 Agent 阅读理解后处理 |
| 住址 | **不识别**，同上 |
| 18 位业务编号 | 默认不启用 `uscc`，故不会误判；启用后有误报风险 |
| 身份证号中间恰好构成手机号 | 身份证校验位合法时优先按身份证整体处理；不合法才可能切成手机号 |
| 港澳台/外籍证件、护照 | 不识别 |
| 分段写的号码（`138 1234 5678`） | **识别不到**，需先去掉分隔符 |
| 身份证后 4 位保留 | 这是可用性取舍；要求完全不可还原时改用 `--id-level` 之外的方式自行处理 |

## 回答建议

- 先说"共发现 N 处，涉及哪几类"，再给脱敏后的文件/文本。
- **每次都要补一句**：本技能不识别姓名与住址，脱敏后仍需人工过一遍。
- 用户要"完全脱敏"或"合规交付"时，说明这只覆盖了有确定算法的几类，
  合规结论不能只依赖本工具。
- 用 `--show-original` 时提醒：这份对照报告本身含原始敏感值，应与原文同等保管。
- 发现识别不到（如分段号码）时，建议先规整格式再跑，而不是手工补打码。
