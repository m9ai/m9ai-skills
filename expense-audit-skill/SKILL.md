# 报销单审计

对一批发报销单做入账前检查：必填项、合计核对、超标、重复票据、疑似拆分。
纯本地运行，不联网、不上传报销数据。

## 何时使用

- 一批报销单入账前先过一遍（"帮我审一下这批报销"）
- 检查有没有拿同一张票报两次（"有没有重复票据"）
- 核对明细加总与报销单声明金额（"合计对不对得上"）
- 查出超标准的费用（"有没有超标的"）
- 找同一人同一天拆成多笔的疑似规避审批（"有没有拆单"）

## 硬性规则

1. **必须执行脚本，不要手工核对合计。** 加总与重复票据号是脚本最该干的事。
2. **本脚本不内置任何限额标准。** 差旅、招待、交通的标准各单位差异极大，
   内置一套"通用标准"只会给出看似权威的错误结论。
   用户没给 `--limit=` 时，**超标检查直接跳过**并在末尾提示，不要替用户编标准。
3. **W 级是提醒不是错误**，不要据此直接退单：
   - W503（费用日期久远）可能是跨期补报，合法
   - W504（同人同日同额）可能是真的两笔不同费用
   - W506（负数）可能是冲销
4. **E405 合计不符要看是不是缺行**：差异金额能对应上某一笔时，多半是那笔没录进来。
5. 票据号校验只判断"是否 8 位数字"，**不判断发票真伪**（真伪需税局查验）。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。

```bash
node scripts/expense.js check <CSV> [选项]
node scripts/expense.js --selftest
```

### 选项

| 选项 | 说明 |
|---|---|
| `--limit=<类型:金额>` | 单项限额，可重复：`--limit=差旅:500 --limit=餐饮:200` |
| `--limits-file=<CSV>` | 限额表，两列：`费用类型,限额` |
| `--declared-total=<金额>` | 报销单声明合计，用于核对明细加总 |
| `--max-age-days=90` | 费用发生日距今超过此天数则提醒 |
| `--require-approver` | 要求审批人必填（该列存在时检查） |
| `--delimiter=,` | 强制分隔符 |
| `--json` | 输出 JSON |

### CSV 列名（自动识别）

| 字段 | 可识别的表头 |
|---|---|
| 费用日期 | 费用日期 / 发生日期 / 日期 |
| 报销人 | 报销人 / 申请人 / 姓名 / 员工 |
| 部门 | 部门 / 所属部门 |
| 费用类型 | 费用类型 / 费用科目 / 类型 / 科目 |
| 金额 | 报销金额 / 金额 |
| 票据号 | 发票号码 / 票据号 / 票据号码 |
| 事由 | 事由 / 摘要 / 费用说明 / 备注 |
| 审批人 | 审批人 / 审核人 |

**必填项**：费用日期、报销人、费用类型、金额、票据号。
列不存在时对应检查自动跳过（不会把"整列缺失"误报成"每行都缺"）。

### 常用示例

```bash
# 先审必填项与重复票
node scripts/expense.js check ./报销明细.csv

# 带标准审
node scripts/expense.js check ./报销明细.csv --limit=差旅:1000 --limit=餐饮:500

# 核对报销单声明金额
node scripts/expense.js check ./报销明细.csv --declared-total=8580.00

# 要求审批人
node scripts/expense.js check ./报销明细.csv --require-approver
```

## 规则编号

| 编号 | 级别 | 含义 |
|---|---|---|
| E401 | 错误 | 必填项为空 |
| E402 | 错误 | 金额无法解析，或为 0 |
| E403 | 错误 | 票据号重复（跨行） |
| E405 | 错误 | 明细加总 ≠ 声明合计 |
| E406 | 错误 | 费用日期无法识别，或在未来 |
| W501 | 提醒 | 超出用户提供的限额 |
| W502 | 提醒 | 缺少审批人（`--require-approver` 时） |
| W503 | 提醒 | 费用发生日距今超过 `--max-age-days` |
| W504 | 提醒 | 同一人同日同额多笔，疑似拆分 |
| W506 | 提醒 | 金额为负，确认是否冲销 |
| W507 | 提醒 | 票据号不是 8 位，确认是否增值税发票号码 |

## 输出解读

```
共 6 笔，合计 8580.00
声明合计 8580.00　明细加总 8580.00　✓ 一致
问题：错误 2 / 提醒 7

--- 按费用类型 ---
  差旅           3 笔       7400.00
  餐饮           1 笔        880.00
```

退出码：`0` 无 E 级问题，`1` 存在 E 级问题，`2` 用法错误。

## 已知取舍

| 情形 | 处理 |
|---|---|
| 限额标准 | **不内置**，必须由用户提供 |
| 发票真伪 | **无法判断**，只校验票据号位数 |
| 分级审批（金额越大层级越高） | 不做，只检查审批人是否填写 |
| 附件是否齐全 | 不做，CSV 里没有该信息 |
| 同一票据分次报销（部分金额） | 会报 E403 重复，需人工确认是否为分次报销 |
| 多人分摊一笔 | 不做分摊，需先按人拆行 |
| 跨币种 | 不支持，需先折算 |

## 回答建议

- 先报三个数：共几笔、合计多少、错误/提醒各几条。
- 有 E403 重复票据号时**优先说**，这是最可能导致退单的问题。
- 未提供限额时要明确说"未做超标检查"，不要含糊地说"未发现超标"。
- W504 疑似拆分要说成"需确认"，不要直接定性为"违规拆单"。
- 合计不符时，帮用户算一下差异金额是否等于某一笔，能对应上就直接指出那一行。
