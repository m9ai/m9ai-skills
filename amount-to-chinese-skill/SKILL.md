# 金额转大写

把阿拉伯数字金额转成符合中国人民银行《正确填写票据和结算凭证的基本规定》的中文大写，
用于发票、收据、合同、支票、报销单等需要大写金额的场合。

## 何时使用

用户给出数字金额并需要大写形式时启用本技能：

- 单条转换（"1234.56 大写怎么写"、"把 8 万块写成大写"）
- 批量转换（"把这批金额都转成大写"、"这个表格里的金额列需要大写"）
- 核对已有大写是否正确

## 硬性规则

1. **禁止凭记忆或口算输出大写。** 大写的「零」规则极易写错，任何结果都必须执行脚本获取。
2. **不要擅自改写脚本给出的「零」。** 规范对个别位置留了可选项（如 `107000.53` 既可写
   「壹拾万柒仟元伍角叁分」也可写「壹拾万零柒仟元伍角叁分」），本实现已固定取其中一种，
   **同一输入永远同一输出**。用户若坚持另一种写法，说明那是规范允许的变体，不要说脚本错了。
3. **金额必须来自用户输入或文件。** 不要替用户假设金额，也不要把近似值当准确值。
4. **负数要提示核实。** 票据场景实际不接受负数，脚本会输出「负…」，此时必须提醒用户确认
   这是否为退款、冲销或录入错误。
5. **批量处理要逐行如实报告。** 解析失败的行以 ⚠️ 标出并给出行号，不要跳过、不要猜值。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。纯本地计算，不联网、不上传。

```bash
node scripts/amount.js <金额> [<金额> ...] [--json]
node scripts/amount.js --file <路径> [--column=N] [--has-header] [--json]
node scripts/amount.js --selftest
```

### 参数说明

| 参数 | 说明 |
|---|---|
| `<金额>` | 支持 `1234.56`、`1,234.56`、`¥1,234.56`、`RMB 1234.56`、全角数字 |
| `--file` | 逐行读取文件，每行一个金额 |
| `--column=N` | 按逗号取第 N 列（从 1 开始），用于 CSV |
| `--has-header` | 跳过首行表头 |
| `--json` | 输出 JSON，便于二次处理 |
| `--selftest` | 跑内置用例（含规范示例），用于验证环境是否正常 |

### 常用示例

```bash
# 单条
node scripts/amount.js 1234.56
# → 1,234.56 → 壹仟贰佰叁拾肆元伍角陆分

# 多条
node scripts/amount.js 1409.50 6007.14 0.05

# 批量文件（第 3 列是金额，首行是表头）
node scripts/amount.js --file ./报销明细.csv --column=3 --has-header

# 环境自检
node scripts/amount.js --selftest
```

## 输出解读

```
行 2: 305.07 → 叁佰零伍元零柒分
行 4: abc    → ⚠️ 无法解析为金额: abc
```

- 左侧是归一化后的金额（千分位 + 两位小数），便于与原文核对
- `⚠️` 行表示解析失败，**必须照原样转达给用户**，不要自行猜测或跳过

## 取舍说明

规范留了可选项的地方，本实现的固定选择如下，如需改变请明确告知：

| 情形 | 本实现输出 |
|---|---|
| 角位为 0、分位不为 0 | 「元」后补「零」：`325.04` → `叁佰贰拾伍元零肆分` |
| 万位为 0、千位不为 0 | 补一个「零」：`100700` → `壹拾万零柒佰元整` |
| 万位为 0、千位也为 0 | 不补：`107000` → `壹拾万柒仟元整` |
| 整数部分为 0 | 写出「零元」：`0.05` → `零元零伍分` |
| 到「元」为止 | 结尾写「整」：`100` → `壹佰元整` |
| 到「角」为止 | 不写「整」：`1409.50` → `壹仟肆佰零玖元伍角` |

## 回答建议

- 直接给出大写结果，并附上归一化后的金额让用户核对原文（`"¥1,234.56 → 壹仟贰佰叁拾肆元伍角陆分"`）。
- 用户是要填票据时，提醒大写金额前通常要加「人民币」三字并顶格填写、不得留空。
- 批量场景先汇总「共 N 条、失败 M 条」，再贴结果；失败行单独列出原因。
