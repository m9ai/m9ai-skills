# CSV 差异比对

按关键列比对两个 CSV，输出哪些行是新增的、哪些被删了、哪些字段被改了。
纯本地运行，不联网、不上传数据。

## 何时使用

- 两版数据对比（"这两个月的表有什么变化"）
- 核对导入前后是否一致（"导入后哪些行变了"）
- 找新增与遗漏（"新版比旧版多了哪些、少了哪些"）
- 逐字段看变更（"订单 1002 到底改了什么"）

## 硬性规则

1. **必须执行脚本，不要人工对。** 上千行的表人工比对必然漏。
2. **必须先确定关键列。** 没有稳定的唯一键时比对结果没有意义——
   要先确认哪一列能唯一标识一行，必要时用多列组合。
3. **默认做数值归一化**：`100` 与 `100.00`、`1,000` 与 `1000` 视为相同，
   因为那只是写法差异。要严格按字符串比对时加 `--exact`。
4. **关键列重复时结果不可信。** 脚本只按第一行比对，并会提示重复，
   此时应先去重再比对，不要直接采信结果。
5. 两表列集合不一致时，只比对共有列，并把各自特有的列列出来——
   **不要说成"这些列没问题"**，它们根本没参与比对。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。

```bash
node scripts/csvdiff.js diff <A表> <B表> --key=列[,列] [选项]
node scripts/csvdiff.js --selftest
```

### 选项

| 选项 | 说明 |
|---|---|
| `--key=列[,列]` | **必填**。关键列，可多个组成组合键（列名或列号） |
| `--compare=列[,列]` | 要比对的列，默认两表共有的所有非关键列 |
| `--exact` | 严格按字符串比较 |
| `--delimiter=,` | 强制分隔符 |
| `--json` | 输出 JSON |

### 常用示例

```bash
# 按订单号比对两版
node scripts/csvdiff.js diff ./v1.csv ./v2.csv --key=订单号

# 组合键
node scripts/csvdiff.js diff ./v1.csv ./v2.csv --key=区域,月份

# 只关心金额变化
node scripts/csvdiff.js diff ./v1.csv ./v2.csv --key=订单号 --compare=金额

# 严格比对（连写法差异也要揪出来）
node scripts/csvdiff.js diff ./v1.csv ./v2.csv --key=订单号 --exact
```

## 输出解读

```
未变更 2，新增 1，删除 0，变更 1

--- 变更（1）---
  1002  （A 第 3 行 → B 第 3 行）
      金额: 1500.00 → 1800.00
      状态: 待付款 → 已发货

--- 新增（B 有 A 无，1）---
  第 5 行　1004
```

- 变更条目给出 A、B 两侧的行号，便于回原表定位
- 空值显示成「（空）」，不会与空字符串混淆
- 关键列重复、列集合不一致都会单独提示

退出码：`0` 无差异，`1` 有差异，可用作同步校验的卡口。

## 已知取舍

| 情形 | 处理 |
|---|---|
| `100` vs `100.00` | 默认视为相同；`--exact` 下视为变更 |
| 关键列重复 | 只按第一行比对，并在报告里提示 |
| 两表列不一致 | 只比对共有列，列出各自特有列 |
| 行顺序变化 | 不影响结果（按关键列匹配，不按行号） |
| 列顺序变化 | 不影响结果（按列名匹配） |
| 关键列大小写/空格差异 | **不做归一化**，"A1" 与 "a1" 算两行 |
| 一个表内关键列为空 | 空键会当作一个合法键值参与匹配，可能误配 |

## 回答建议

- 先报四个数：未变更、新增、删除、变更各多少。
- 变更条目要逐字段说明"从什么变成什么"，不要只说"有变更"。
- 有关键列重复时**必须先说**：这个前提下的结果不可信，建议先去重。
- 有特有列时说明"这些列没参与比对"，不要让用户误以为全表都核对过了。
- 用户没指定关键列时，先问哪一列能唯一标识一行，或建议用组合键——
  不要随手挑第一列当主键。
