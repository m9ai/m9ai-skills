# cron 表达式解析

把 cron 表达式翻译成人话，并算出接下来几次执行时间。
纯本地运行，不联网。

## 何时使用

- 看不懂一个 cron 表达式（"这个 cron 是什么意思"）
- 确认执行时间是否符合预期（"*/15 * * * * 到底几点跑"）
- 验证自己写的表达式（"我想每周一到周五 9 点跑，写得对吗"）
- 排查定时任务没按时执行（"按这个表达式下次该什么时候跑"）

## 硬性规则

1. **必须执行脚本，不要凭记忆口算。** 尤其「日」与「周」同时出现时的语义，人很容易搞错。
2. **「日」与「周」都受限时按 OR 匹配**（满足任一即触发），这是 Vixie cron 的行为。
   很多人以为是 AND，那会导致判断完全相反。脚本会在这种情况下主动提示。
3. **不支持 Quartz 专有语法**：`L`（最后一天）、`W`（最近工作日）、`#`（第几个周几）、
   7 段带年表达式。遇到会**明确报错**，不会猜一个错误答案出来。
4. **时间按系统本地时区计算**。服务器时区与本地不一致时结果会不同，
   排查线上问题时要确认部署环境的 `TZ`。
5. 描述文本是**近似表达**，覆盖常见组合；罕见组合以「各字段」与「接下来 N 次」为准。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。

```bash
node scripts/cron.js explain "<表达式>" [--next=5] [--from=<ISO>] [--lang=zh|en] [--json]
node scripts/cron.js next "<表达式>" [--count=5] [--from=<ISO>]
node scripts/cron.js --selftest
```

**表达式要加引号**，否则 shell 会把 `*` 展开成文件名。

### 选项

| 选项 | 说明 |
|---|---|
| `--next=` / `--count=` | 输出接下来几次，默认 5 |
| `--from=<ISO>` | 起始时间，默认当前时间 |
| `--lang=zh\|en` | 描述语言，默认中文 |
| `--json` | 输出 JSON |

### 语法支持

| 语法 | 含义 | 例 |
|---|---|---|
| `*` | 所有取值 | `* * * * *` 每分钟 |
| `,` | 列表 | `0,30 * * * *` 每小时第 0 与 30 分 |
| `-` | 范围 | `0 9 * * 1-5` 周一至周五 9 点 |
| `/` | 步长 | `*/15 * * * *` 每 15 分钟 |
| `?` | 同 `*`，用于「日」「周」二选一 | `0 0 1 * ?` 每月 1 日 |
| `JAN-DEC` `SUN-SAT` | 月份与星期别名 | `0 0 * * MON` |

支持 5 段（分 时 日 月 周）与 6 段（秒 分 时 日 月 周）。
星期 `0` 与 `7` 都表示周日。

### 常用示例

```bash
# 解释并给出接下来 3 次
node scripts/cron.js explain "0 9 * * 1-5" --next=3

# 英文描述
node scripts/cron.js explain "*/15 * * * *" --lang=en

# 从指定时间开始算
node scripts/cron.js explain "0 0 1 * *" --from=2026-03-05T00:00:00

# 只要时间列表
node scripts/cron.js next "0 9 * * *" --count=10
```

## 输出解读

```
表达式: 0 9 * * 1-5
含义:   周一至周五 09:00

各字段
  分  0
  时  9
  日  1,2,3,…（31 个）
  月  1, 2, …, 12
  周  1, 2, 3, 4, 5

接下来 3 次执行（从 2026-03-05 00:00:00 起，本地时区）
  2026-03-05 09:00:00  周四
  2026-03-06 09:00:00  周五
  2026-03-09 09:00:00  周一
```

带星期几便于核对跨周末的场景。表达式非法时退出码 `2` 并给出具体原因。

## 已知取舍

| 情形 | 处理 |
|---|---|
| Quartz `L` / `W` / `#` | **明确报错**，不支持 |
| 7 段带年表达式 | **明确报错**，不支持 |
| 「日」与「周」同时受限 | 按 OR 匹配，并在输出里提示 |
| 2 月 30 日这类矛盾表达式 | 报"找不到匹配时间"而非返回错误结果 |
| 时区 | 系统本地时区，不指定 TZ |
| 夏令时 | 由系统 Date 处理，跨夏令时的行为以系统为准 |
| 闰秒 | 不涉及 |
| `@yearly` `@daily` 这类宏 | 不支持，需展开成标准五段 |

## 回答建议

- 先给「含义」，再给「接下来几次」——用户通常最关心这两项。
- 「日」与「周」都受限时**必须说明是 OR**，这是最容易误解的地方。
- 用户给出的表达式非法时，直接转述脚本的错误原因，不要猜。
- 涉及线上定时任务时提醒：脚本按本地时区算，请确认部署环境的 `TZ` 设置。
- 用户想"每 N 分钟"但写成了 `N * * * *`（那是"每小时第 N 分"）时，
  主动指出差别并给出正确写法 `*/N * * * *`。
