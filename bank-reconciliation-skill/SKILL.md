# 银行对账

把企业账与银行账按**金额 + 日期**模糊匹配，输出未达账项与差异。
纯本地运行，不联网、不上传账单数据。

## 何时使用

- 月末对账（"帮我对一下这个月的银行账"）
- 找未达账项（"哪些是企业记了银行没到的"）
- 余额对不上时定位差异（"账面和银行差 300 块，差在哪"）
- 手续费被拆成两笔导致金额对不上（"这笔 23000 怎么银行是两笔"）

## 硬性规则

1. **必须执行脚本，不要手工比对。** 几十上百笔的手工比对必然漏项。
2. **金额一律转成「分」的整数再比较**，绝不用浮点直接比相等。
3. **默认日期容差 3 天**（覆盖 T+1 到账）。用户明确说"当天到账"时改成 0。
4. **两侧借贷方向相反时用 `--flip-b`**，不要手工改数据文件。
5. **本工具不做余额调节表。** 它输出的是差异明细；调节表的编制口径（加/减哪些项）
   要由用户按本单位会计政策决定，不要把输出直接说成"调节后余额"。
6. 金额差很小的一对会被标为**可疑近似**而不是直接匹配——因为那可能是记错金额，
   也可能是真的一笔手续费，只有人能判断。

## 执行方式

在**技能根目录**下用 Bash 执行，`node` 需 16 及以上版本。

```bash
node scripts/reconcile.js match <企业CSV> <银行CSV> [选项]
node scripts/reconcile.js --selftest
```

### 选项

| 选项 | 说明 |
|---|---|
| `--a-date=` `--a-amount=` `--a-desc=` | 企业侧列，可填列名或列号（1 起） |
| `--b-date=` `--b-amount=` `--b-desc=` | 银行侧列，同上 |
| `--days=N` | 日期容差天数，默认 3 |
| `--flip-b` | 银行侧金额取反（两侧借贷方向相反时） |
| `--max-split=N` | 一笔对多笔的最大拆分笔数，默认 3；设 `1` 关闭拆分匹配 |
| `--near-ratio=0.02` | 可疑近似的金额相对差阈值，默认 2%（同时有 1 元的绝对下限） |
| `--delimiter=,` | 强制分隔符 |
| `--json` | 输出 JSON |

列名自动识别：日期（交易日期/记账日期）、金额（交易金额/发生额）、
摘要（对方户名/备注/用途）。识别不到金额列时会报错退出。

### 常用示例

```bash
# 常规对账
node scripts/reconcile.js match ./企业账.csv ./银行流水.csv

# 两侧方向相反
node scripts/reconcile.js match ./企业账.csv ./银行流水.csv --flip-b

# 严格：只认同一天
node scripts/reconcile.js match ./企业账.csv ./银行流水.csv --days=0

# 关闭拆分匹配（只想看 1:1）
node scripts/reconcile.js match ./企业账.csv ./银行流水.csv --max-split=1
```

## 匹配逻辑

1. **第一轮 1:1**：金额精确相等（以「分」比较）且日期差 ≤ 容差，
   有多个候选时取**日期最近**的一笔。
2. **第二轮 1:N**：一笔企业账等于多笔银行账之和，默认最多 3 笔，
   用于本金+手续费、合并打款被拆分的情形。拆分后每一笔仍要满足日期容差。
3. 剩下的分别是**仅企业有**（未达账项）与**仅银行有**。
4. 两侧都剩、日期接近但金额差很小的，标为**可疑近似**，不自动匹配。

金额无法解析的行会被跳过并在末尾提示数量，**不会静默丢弃**。

## 输出解读

```
已匹配 4 组（1:1 3 组，拆分 1 组）
仅企业有 1 笔，合计 -1234.56　← 未达账项
仅银行有 2 笔，合计 -1201.90

--- 拆分匹配（一笔对多笔之和）---
  A 行4 -23000.00 = B 行4 -22900.00 + B 行5 -100.00

--- 可疑近似（日期接近但金额不等）---
  A 行6 -1234.56 ≈ B 行7 -1234.00　差 0.56　报销差旅
```

退出码：`0` 完全匹配，`1` 存在未达账项，`2` 用法错误。

## 已知取舍

| 情形 | 处理 |
|---|---|
| 多笔同额 | 按日期最近贪心匹配，不保证全局最优 |
| 拆分匹配 | 子集规模 ≤ 3；候选超过 60 笔时跳过该轮并放弃拆分 |
| 手续费单独扣收 | 会被拆进 1:N 匹配；若企业账未记手续费则落入"仅银行有" |
| 汇总入账（多笔记成一笔） | 能由 1:N 覆盖；N > 3 时匹配不到 |
| 余额调节表 | **不生成**，只给差异明细 |
| 跨币种 | 不支持，需先折算成同一币种 |

## 回答建议

- 先报三个数：已匹配多少组、仅企业有几笔（合计多少）、仅银行有几笔（合计多少）。
- 有拆分匹配时单独说一句，因为那通常就是"金额对不上"的原因。
- 可疑近似项要**提示人工确认**而不是替用户判定：可能是录入错误，也可能是真实差异。
- 用户问"调节后余额是多少"时，说明本工具不编制调节表，并把未达账项清单给他。
- 未达账项里出现"结息""手续费""在途"时要提示：这类通常是企业未记账，需补记。
